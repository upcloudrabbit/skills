# Source Code Read 文档章节标准

本文档定义 `/source-code-read` 生成和整理文档时必须使用的章节结构与标题层级。
每类文档的章节顺序和标题是**固定**的，不得自行改名、删减或重排必需章节；章节确实不适用于当前项目时保留标题并写明原因。

各章节的内容编写规范见 [document-content.md](document-content.md)。

## 工程目录文档章节

```markdown

> 上次修改：{_timeStr}

## 技术栈与项目概述

## 重点关注

## 阅读路线

（按新手、维护者、排障者、扩展开发者给出阅读顺序）

## 工程概览文档章节

工程概览文档（`工程概览.md`）由 `init` 时自动生成，描述整个项目的源码目录结构。

```markdown
# {工程名} 工程概览
> 上次修改：{_timeStr}

## 工程目录结构

（一段话介绍当前工程源码的目录结构总体组织方式）

## 目录结构图

```mermaid
{_mermaidThemeInit}
graph TD
  根目录 --> src
  根目录 --> config
  src --> moduleA
  src --> moduleB
  src --> moduleC
  click 根目录 "../工程目录.md" "回到目录"
```

（图中每一级节点都要有简要说明，用节点标签或注释标注）

## 目录说明

### 根目录

（说明根目录下存放的顶层文件/目录的作用）

### src/ 源码目录

（一段话描述 src/ 下存放的核心内容）

#### src/moduleA/ —— {模块A中文名}

（一段话描述该目录存放的文件及其职责）

#### src/moduleB/ —— {模块B中文名}

（一段话描述该目录存放的文件及其职责）
```

## 模块文档章节

模块文档用于 `init` 生成的每个模块文档，以及 `update` 增补模块内容时的目标结构。

```markdown
# {模块中文名}
> 上次修改：{_timeStr}

## 重点关注
## 1. 模块定位与职责边界
## 2. 架构关系与依赖
## 3. 入口与调用方式
## 4. 核心概念与领域模型
## 5. 关键流程
## 6. 核心实现细节
## 7. 数据结构、配置与外部协议
## 8. 异常、边界与降级处理
## 9. 并发、生命周期与性能
## 10. 扩展点、测试点与维护建议
## 11. 文件职责表
## 12. 代码引用索引
```

## 核心源码阅读文档章节

核心源码阅读文档用于对核心模块或关键功能进行细致的源码分析。由 `init` 或 `update` 生成，也可单独生成。
文档数量不固定，按实际需要选择需要深入分析的核心模块或功能。

```markdown
# 源码分析：{核心模块/功能名}
> 上次修改：{_timeStr}

## 阅读向导
## 1. 分析范围与目标
## 2. 核心类/函数全景
## 3. 关键数据结构
## 4. 主线流程逐行解读
## 5. 分支与边界处理
## 6. 设计模式与架构决策
## 7. 性能与资源分析
## 8. 潜在问题与改进建议
## 9. 文件职责表
## 10. 代码引用索引
```
