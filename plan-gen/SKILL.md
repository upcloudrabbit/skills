# Plan Gen — 需求计划生成 Skill

根据用户提供的需求描述，自动分析、拆解并生成为结构化的 Markdown 计划文件，
输出到项目工程路径下的 `plan/` 目录。

---

## 职责分工

| 角色 | 职责 | 做 | 不做 |
|------|------|----|------|
| **主 agent** | 编排与调度 | 解析指令、确定任务序列、启动子 agent、检查结果、输出最终文件清单 | 文件分析、内容生成等具体执行 |
| **子 agent** | 执行具体任务 | 需求分析、任务分解、文件生成 | 调度决策、跨任务传递上下文 |

所有子 agent 统一使用 `subagent_type: general-purpose`。

---

## 指令总览

| 指令 | 功能 |
|------|------|
| `create` | 根据需求生成新的计划文件 |
| `update` | 更新已有计划文件 |
| `help` | 输出简要帮助 |

---

## 通用规范

### 1. 输出路径

- 默认路径：当前项目工程根目录下的 `plan/` 目录（由主 agent 自动确定）
- 路径不存在时自动创建
- 如需输出到其他路径，在需求描述中说明

### 2. 文档规范

- **日期**：文档顶部标注 `YYYY-MM-DD HH:mm` 格式的上次修改时间
- **命名**：计划文件名使用中文，如 `用户认证模块实现计划.md`
- **vibe coding 导向**：计划按**实现顺序**编排步骤，每一步描述清楚后交由 AI 逐步编码实现，完成后进入下一步

### 3. 画图约定

所有涉及画图场景，**统一使用 Mermaid**。每个 Mermaid 代码块首行插入 `%%{init: {"theme": "neutral"}}%%`。

| 场景 | 优先使用 | 兜底 |
|------|----------|------|
| 调用流程/交互 | `` ```mermaid `` + `%%{init: {"theme": "neutral"}}%%` + sequenceDiagram | 文字流程 |
| 状态流转 | `` ```mermaid `` + `%%{init: {"theme": "neutral"}}%%` + stateDiagram-v2 | 文字状态表 |
| 流程图/算法逻辑 | `` ```mermaid `` + `%%{init: {"theme": "neutral"}}%%` + flowchart | 步骤列表 |
| 架构/模块依赖 | `` ```mermaid `` + `%%{init: {"theme": "neutral"}}%%` + graph | 层次列表 |

#### Mermaid 语法陷阱

子 agent 生成 Mermaid 图时注意以下常见问题：

- **特殊字符用引号包裹**：节点标签中含 `( )` `[ ]` `{ }` `"` `:` 等时，必须用双引号包裹，如 `class "User(Entity)"`
- **时序图参与者**：名称含空格/特殊字符时用引号包裹并用 `as` 起别名，如 `participant "API Gateway" as Gateway`
- **流程图节点转义**：特殊字符在节点定义处用引号，而非关系行，如 `A["节点(带括号)"]`
- **禁用 HTML 标签**：Mermaid 不支持 `<br/>` 等 HTML 标签，换行用 `\n` 或 `</br>`

#### Mermaid 语法校验

每次生成或修改 Mermaid 图后，**必须自行校验语法正确性**，直至渲染通过：

1. **写入后立即校验**：将 Mermaid 代码块写入文件后，立即自行审查校验
2. **校验方式**：子 agent 根据 Mermaid 语法规范逐项检查生成的代码：
   - 检查特殊字符是否已用双引号包裹（`( ) [ ] { }` 等）
   - 检查参与者名称是否含空格，必要时用 `as` 起别名
   - 检查关系/连线语法是否正确（箭头方向、`-->` `->>` 等）
   - 检查 sequenceDiagram/stateDiagram-v2 等类型声明是否匹配实际语法
   - 检查时序图 participant 声明是否正确
   - 检查流程图节点定义是否完整
   - 确认首行已插入主题初始化 `%%{init: {"theme": "neutral"}}%%`
3. **修复与重试**：
   - 发现问题 → 定位原因 → 修复 → 重新校验
   - 循环直到校验通过，**最多重试 5 次**
   - 超限后使用兜底方案（文字流程 / 步骤列表）替代
4. **常见失败原因排查**：
   - 特殊字符未引号包裹 → 加双引号
   - 节点 ID 含空格 → 改用驼峰或下划线
   - 关系语法错误（如缺少 `:`） → 检查箭头/连线格式
   - 缩进/换行问题 → 清理多余空白

#### 流程图步骤编号与说明

生成 `flowchart` 类型的 Mermaid 图时，必须遵守以下规范：

1. **节点编号**：流程图的每个步骤节点使用分层编号命名，用节点 ID 中的数字序号表达层级与顺序：

   | 层级 | 格式 | 示例 |
   |------|------|------|
   | 一级步骤 | `1` `2` `3` … | `1[解析请求]` |
   | 二级子步骤 | `1.1` `1.2` `2.1` … | `1.1[验证参数]` |
   | 三级子步骤 | `1.1.1` `1.1.2` … | `1.1.1[格式校验]` |

2. **步骤说明表**：在 Mermaid 代码块下方紧跟着一个步骤说明列表或表格，详细说明每一步在做什么：

   ````markdown
   ```mermaid
   %%{init: {"theme": "neutral"}}%%
   flowchart LR
     1[解析请求] --> 1.1[验证参数]
     1.1 --> 1.2[执行逻辑]
     1.1 --> 1.3[降级处理]
     1.2 --> 2[返回结果]
   ```

   | 步骤 | 说明 |
   |------|------|
   | 1 解析请求 | 从 HTTP 请求中提取参数和 body，反序列化为内部结构体 |
   | 1.1 验证参数 | 校验必填字段、格式合法性，失败走 1.3 降级 |
   | 1.2 执行逻辑 | 调用核心业务逻辑处理请求 |
   | 1.3 降级处理 | 参数不合法时返回默认结果或错误码 |
   | 2 返回结果 | 将处理结果序列化为 JSON 并写入响应体 |
   ````

3. **说明内容要求**：每步说明应包含「做了什么」+「关键决策或边界条件」（如有），如失败分支、数据流向等

### 4. 跨子 agent 变量

| 变量 | 含义 | 设置时机 |
|------|------|----------|
| `_planPath` | 计划输出目录（绝对路径） | create/update 步骤 1 |
| `_timeStr` | 当前时间字符串 `YYYY-MM-DD HH:mm` | 每次文件写入前 |
| `_maxConcurrency` | 最大并行子 agent 数量 | create 步骤 2 |
| `_verifyMethod` | 验证方式描述 | create 步骤 2 |

## `create` — 生成计划

### 执行流程

1. **确认输出路径 `_planPath`**：
   - 询问用户："计划文件输出目录？（默认：项目根目录/plan）"
   - 用户未输入时使用默认值：项目工程根目录下的 `plan/`
   - 路径不存在时自动创建
   - 如目录下已有同名文件，列出内容并询问是否覆盖或创建新文件
   - 在同一会话中记住 `_planPath`

2. **收集必要信息**：依次向用户确认以下三项内容，分别存入对应变量：

   a) **需求内容** → 作为 `requirement`
   - 询问："请描述需求内容："
   - 用户输入自然语言需求描述

   b) **验证方式** → 存入 `_verifyMethod`
   - 询问："验证方式是什么？（如：人工审查 / 自动化测试 / 预览截图确认 / 其他）"
   - 如用户输入模糊，引导选择具体验证手段

   c) **最大并行 subagent 数量** → 存入 `_maxConcurrency`
   - 询问："最大同时启动几个子 agent？（推荐 2-3，默认 3）"
   - 用户未指定时默认为 3

3. **启动计划生成子 agent**：

   ```
   Agent:
     description: 分析需求并生成计划
     prompt: |
       根据以下需求生成结构化计划文件。

       需求描述：
       {requirement}

       验证方式：{_verifyMethod}

       输出路径：{_planPath}
       文件名：{planFileName}.md
       当前时间：{_timeStr}
       最大并行子 agent 数：{_maxConcurrency}

       要求：
       1) 分析需求，明确核心目标和范围
       2) 按**实现顺序**拆解为可执行的任务步骤，每步标注：
          - 步骤编号（1 / 2 / 3 …）
          - 步骤名称
          - 步骤描述（做什么、验收标准，参照验证方式"{_verifyMethod}"定义验收条件）
          - 涉及的文件或模块
       3) 上一步完成并验证后，才能进入下一步，形成线性推进链路
       4) 如需求涉及 UI 界面或架构变更，生成对应的 Mermaid 图
       5) ⚠ **禁止越界执行**：本计划仅供描述和编排任务，不得在实际项目中创建、修改或删除任何代码文件。一切编码工作留待后续由其他 agent 按此计划执行。

       文件结构：
       # {标题}
       > 上次修改：{_timeStr}

       ## 目标
       一句话概括本次计划的核心目标

       ## 需求分析
       将用户需求整理为清晰的条目，明确范围与边界

       ## 验证方式
       {_verifyMethod}

       ## 实施步骤
       | 步骤 | 任务 | 描述与验收标准 | 涉及文件/模块 |
       |------|------|---------------|---------------|
       | 1 | 任务名 | 做什么，如何验证完成 | 路径 |
       | 2 | 任务名 | 做什么，如何验证完成 | 路径 |

       ## 风险与注意事项
       - 已知风险及应对方案
       - 需要确认的事项

       写入 {_planPath}/{planFileName}.md。
   ```

4. **输出结果**：
   ```
   create 完成：
     - 创建 {planFileName}.md（共 {N} 个实施步骤，最大并发 {_maxConcurrency}）
   ```

## `update` — 更新计划

### 执行流程

1. **确认输出路径**（可沿用 `_planPath`）
2. **列出已有计划文件**：列出 `_planPath` 下所有 `.md` 文件，让用户选择要更新的文件
3. **启动更新子 agent**：

   ```
   Agent:
     description: 更新计划文件
     prompt: |
       更新计划文件 {_planPath}/{targetFile}。
       当前时间：{_timeStr}

       需求变更：{changes}

       操作规范：
       1) 读取当前计划文件内容
       2) 根据需求变更更新对应章节
       3) 更新上次修改时间为 {_timeStr}
       4) 保持文件结构完整，不丢失原有有效信息
       5) 保存文件
   ```

4. **输出结果**：
   ```
   update 完成：
     - 更新 {targetFile}
   ```

## 注意事项

1. **路径自动创建**：`plan/` 目录不存在时自动创建，无需用户手动操作。
2. **会话记忆**：同一会话中 `_planPath` 自动沿用，无需重复确认。
3. **子 agent 容错**：子 agent 返回 null 或无效结果时记录日志并告知用户。
4. **增量更新**：update 只变更目标章节，不重写整个文件。
5. **禁止越界执行**：本 skill 仅负责生成和维护计划文档，不得在实际项目中创建、修改或删除任何代码文件。编码工作留待后续由其他 agent 按计划执行。
